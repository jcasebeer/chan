PLAN 13 - COMPLETE 
-leverage browser caching to cut bandwidth,
especially for uploads (the biggest hog) -uploads are immutable (path
is uploads/<rowid>.<ext> and ids are AUTOINCREMENT, never reused),
so serve them with Cache-Control: public, max-age=1y, immutable so the
browser serves repeat views from cache with no revalidation round-trip
(mongoose already sends an Etag for a cheap 304 after expiry/eviction)
-static assets (style.css, htmx.min.js) can change, so cache them for
a modest window (max-age=1h) and rely on the Etag for revalidation
after that -dynamic HTML (catalog, thread pages) must stay fresh,
so send Cache-Control: no-cache so it is always revalidated and never
heuristically cached stale Note- Claude wrote this plan after completing
the work during a freeform chat
